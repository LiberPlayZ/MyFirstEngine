1️⃣ Deepen Your CMake & Project Structure Knowledge

Why?
Because before building complex systems (rendering, physics, input), you must know how to:

add more modules

create internal/private libraries

link external libraries

use FetchContent

handle debug/release configurations

Topics to learn now:

✔ Header / source organization
✔ Engine as static/shared library
✔ target_link_libraries
✔ target_include_directories (PUBLIC / PRIVATE / INTERFACE)
✔ FetchContent (modern dependency download)

💡 After this, you can easily add:

GLFW

SDL2

GLM

Vulkan SDK

OpenGL loaders

ImGui

👉 If you want, I can teach you “CMake for game engines” in a structured mini-course.

2️⃣ Learn How to Create a Window + Game Loop

This is the first real engine component.

You pick GLFW or SDL2.

You learn:

how to create a window

how to process events

how to create the main loop

controlling FPS

closing the window

This gives you:

while (running) {
    engine.Update();
    engine.Render();
}


This is the backbone of all engines.

3️⃣ Add a Logging System

All real engines have structured logs.

Just simple at first:

[INFO]: Window created
[WARN]: Missing shader file
[ERROR]: Renderer initialization failed


Good topics:

✔ macros
✔ color output
✔ log levels
✔ file logging

Later you can add:

async logging

profiling

time stamps

4️⃣ Add a Math Library (or use GLM)

A renderer needs math:

vec2 / vec3 / vec4

matrices

transforms

quaternions

projection matrices

You can either:

use GLM (highly recommended), or

write your own minimal math types

This is required before learning rendering.

5️⃣ Add Rendering

Choose a backend:

OpenGL (easiest)

Vulkan (most professional, harder)

DirectX (Windows-only)

Rendering topics:

📌 For OpenGL:

creating context

loading functions (glad)

shaders

vertex buffers

drawing triangles

textures

camera

2D or 3D

📌 For Vulkan:

instance

devices

swap chain

render pass

pipeline

synchronization

We can start with OpenGL first — much easier.

6️⃣ Add an Input System

Keyboard & mouse handling through GLFW/SDL2.

You build something like:

if (input.IsKeyDown(KEY_W)) {
    camera.MoveForward(deltaTime);
}

7️⃣ Add a Resource/Asset System

Load files:

textures

models

shaders

audio

Learn about:

caching

memory management

resource paths

8️⃣ Add a Component / Entity System

After you have rendering, input, resources, you can start building “engine architecture”.

You learn:

ECS (Entity Component System)

Entities = IDs

Components = data

Systems = logic

Or a simpler OOP-based engine architecture:

GameObject

Transform

MeshRenderer

Camera

⭐ The Path in Summary (Ordered)**

Here’s the recommended order very clearly:

CMake mastery (next immediate step)

Window + game loop

Logging system

Math layer (GLM)

OpenGL or Vulkan rendering

Input system

Resource loading

Scene / ECS

UI, audio, physics, tools (advanced)
